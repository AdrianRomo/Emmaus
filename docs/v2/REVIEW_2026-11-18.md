# Adversarial review, 2026-11-18

Three independent reviewers (visual direction, product/UX, interaction/frontend) walked four journeys
in the running app on their own data copies, at 360/390/820/1440, with Playwright measurements and axe;
a fourth critic reviewed the two rebuilt homes and the serving interaction from screenshots. None of
this is user research: `USABILITY_TEST.md` is the plan for that, not done yet.

## Verdict (merged)

The two rebuilt homes were calm and well made; the product one step away was not. Emmaus was built
around destinations (tabs, modules, a table) more than around each person's open loops: an answered
item stayed raised, a decision reloaded the page and lost the person's place, the camp administrator
could not see minors' authorizations at all, and the same object or state was drawn several ways.
The one signature (the arch) was legible only where it carried information.

Kept: ink text, one action colour, the warm ground; the serving question (date, question, two answers);
actions in place (busy in 1–2 ms, server answer ~120 ms, failure recovery ~15 ms); CLS 0, axe 0, no
overflow on every screen swept; the camp's line of arches under «27 de 34»; the interview's step flow.
